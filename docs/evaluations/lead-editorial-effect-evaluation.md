The implemented participant interface is:

```sh
python tools/evaluate_lead_editorial.py grade --packet /path/to/review-packet.json --out-dir /path/to/new-author-review
python tools/evaluate_lead_editorial.py grade --packet /path/to/review-packet.json --out-dir /path/to/new-reader-review
```

Run each command independently for a different real person. The command asks for a self-attributed reviewer ID and author_intent or reader_editor role, then displays each case's source material, brief, anonymous sides and all scoring anchors. It reads only the blinded packet; captures, arm mappings, provider/model and costs are not command inputs. Each person reviews all nine cases independently, using different reviewer IDs for different actual people. Two IDs from the same person do not meet the independent-review requirement. Scores use 0–4 or unobserved with reasons and uncertainty; missing output or approval context requires unobserved. Participants can edit before saving or use /cancel. EOF/cancellation produces no complete review.

For later compare ingestion, the operator places each participant output directory directly under the capture artifact root, using its distinct directory name as the review_record path prefix. Grade does not inspect that capture root or its files. Each absent output directory is created exclusively and contains reviews.json plus review-record.json, cited by hash as participant evidence. Existing output is never overwritten; an existing output directory is an invalid-input refusal (exit 2). Exit 0 means complete validated publication, 3 cancellation/EOF, 2 invalid input, and 1 a filesystem error. A filesystem error during writing may leave a partial directory; retain and inspect it, and do not treat it as a complete review or overwrite it on retry. The compare command validates each strict review against the exact packet and evidence record. For a paired assessment, an evaluation operator combines the two independently saved reviews arrays into one existing REVIEWS-format file with unchanged comparison_id and review_packet_sha256; retain each review's evidence path relative to the capture artifact root used by compare (or copy its record under that root with the matching hash). The operator must not rewrite scores or evidence. Keep the original per-participant directories and review records; a combined file is a derived input, not a replacement for the independent records. The tool does not authenticate identity or prove genuine blinding merely from hashes.
